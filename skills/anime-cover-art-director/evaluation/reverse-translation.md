# 反向转译与成品验收
目的：检验创意在实际成果中是否仍然存在，而非文案是否解释得好。候选阶段只可预判；新成品或核心机制受影响的修改后执行。以原契约为最终对照。
1. 观察实际成品，尽量暂不借助研究说明，描述可见结构、实际行为或可观察关系及可能替代解释。标题/功能标签若属正式作品可保留；另做去说明检验。有独立未见方案的观察者/Agent才称盲测，否则称非盲反向检查，不伪造用户反馈。
2. 回到原方案，逐项对应不可替代核心→可见/可操作证据→保留、部分保留、缺失或无法验证。区分主题感知与精确规则；好看或说明图有规则不等于真实实现。可以从实际物品/程序检查相同条件下不同状态、接口、反馈、尺寸等；静态渲染无法证明功能、实体拼装或多视图一致。
3. 独立评估创意、表达、功能/工程及硬约束（读 `design-critic.md` 如需完整批评）。表达保真与实际机制实现分别给结论；目标只要概念图时不把未制造当作视觉失败，也不冒称生产稿。只有实际证据才能宣称通过；标注预判及未验证项。
4. 核心关系退化为装饰、证据矛盾或功能不成立时，优先在确认方向内修复表达/实现；必要时回到转译。重大创意变更先征求用户许可。局部修改仅检查受影响项。报告具体证据与剩余风险，不强制长表格或综合分。
